How it works

  1. 01

    Tap your passport

    The phone reads DG1 and the Security Object Document over NFC, using ICAO 9303 BAC. Nothing is uploaded.

  2. 02

    Prove on-device

    A Noir circuit (UltraHonk) verifies the passport signature chain and derives a stable nullifier. Proving runs on your phone in 5–15s via Mopro.

  3. 03

    Register on-chain

    Submit the proof to VerificationRegistry. Protocols read isVerified(wallet) for personhood and nullifierOf(wallet) for sybil dedup.

What's actually on-chain

Your passport never leaves the phone. No name, DOB, nationality, or document number is ever published.

Stored on-chain

  • An opaque nullifier — a one-way hash derived from your passport
  • The wallet address that registered it
  • Registration timestamp and expiry (rounded to 90-day buckets for privacy)
  • The zero-knowledge proof bytes

Never on-chain

  • Name, date of birth, nationality, sex
  • Passport number, issue date, MRZ
  • DG1 / SOD bytes, RSA signatures, document images
  • Anything that could re-identify the holder

The single-tier trade-off

Every wallet you sigilize under the same passport shares the same on-chain nullifier — they're publicly linkable to each other. Wallets you don't sigilize stay anonymous. This is an explicit, opt-in design choice: simple, auditable sybil resistance in exchange for cross-wallet linkability of accounts you choose to attest.

For protocols

A single mapping lookup gives any contract or off-chain service two things: whether a wallet is attested to a real human, and a stable per-passport identifier for deduplication. No SDK, no off-chain attestation server — just a public on-chain read.

Personhood

One-line gating

isVerified(wallet) returns true if a real human is currently attested behind that address. Use it to gate airdrop claims, faucet drips, governance actions, onboarding bonuses — anywhere bots and farms break your unit economics.

Sybil resistance

One passport, one share

nullifierOf(wallet) returns a stable opaque identifier — same value for every wallet a person has sigilized. Track it in a seen[] set and a single passport can only participate once, no matter how many wallets it controls.

Solidity Standard integration pattern 
// Gate on real personhood AND ensure one share per passport.
if (!sigil.isVerified(msg.sender)) revert NotVerified();

bytes32 nullifier = sigil.nullifierOf(msg.sender);
if (claimed[nullifier]) revert AlreadyClaimed();
claimed[nullifier] = true;

// ... proceed with the per-human action.

What this unlocks

⤓

Airdrops

One claim per real human, even when they hold ten wallets.

⊙

DAO voting

One-person-one-vote without KYC, plain Sybil-resistant tallies.

⊞

Quadratic funding

Matching pools that aren't gameable by spinning up wallets.

⌬

Onboarding rewards

Per-person sign-up bonuses that don't get farmed into the ground.

◇

Reputation & reviews

One verifiable opinion per real person, not per generated identity.

⊜

Rate limiting

Per-human quotas instead of per-wallet — bots can't outscale you.

Off-chain works the same way: any backend can eth_call the registry before issuing an API key, validating a signup, or accepting a review. Reads are free and don't touch the user's phone.
